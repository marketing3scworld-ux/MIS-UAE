# BME MIS — Project Map (read this first)

**What it is:** an internal web app for **Brilliant Minds Events LLC** that holds staff
profiles, stores their documents (Emirates ID, passport, OHC, BFHC, visa, bank proof,
photo), tracks each document's expiry, and emails alerts before anything lapses.

**Shape of the system (one line):**
Browser → **one Next.js app** (React pages + server-side actions) → **Prisma** → **PostgreSQL**.
Uploaded files are saved to disk (`UPLOAD_DIR`) and served through a login-protected route.
A nightly in-process job scans for expiries and sends emails. Emirates-ID photos are read by
Claude (Anthropic API) to pre-fill the form.

> **Key point for deployment:** the front end and back end are the **same** Next.js process.
> There is **no separate backend/API server** to run. "Backend" = server-side code *inside* Next
> (the `actions.ts` files and the handlers under `src/app/api`). You deploy **one** Node app + **one** database.

## Database (Prisma → PostgreSQL)

`prisma/schema.prisma` is the single source of truth; `prisma migrate deploy` builds every table
on a fresh database. Main tables:

| Table | Holds |
| --- | --- |
| `Client` / `Project` | Phase 2 — clients and their events; staff are scheduled onto a Project |
| `Deployment` | Phase 2 — one staff member, one shift, one project: schedule AND actuals in one row |
| `DeploymentAudit` | Phase 2 — field-level change log behind the approval workflow |
| `Staff` | one row per employee — name (EN + AR), Emirates ID, category, mobile, nationality, service & residence location, employment status, blacklist flag, per-document expiry dates, bank details |
| `StaffDocument` | uploaded files (versioned) linked to a staff member — type (EID front/back, passport, OHC, BFHC, visa, short-term agreement, bank proof, photo), expiry, handling status |
| `User` | app logins — role, Operations-Head flag, **Super-Admin** flag, manager (for escalation) |
| `Notification` | in-app expiry alerts |
| `AppSetting` + `CategoryOption` / `LocationOption` / `NationalityOption` / `BankOption` | tunable engine settings + editable dropdown lists |

## How the main flows work

- **Browse / edit staff** — a server component queries Prisma → Postgres; edits run through
  server actions (`staff/[id]/actions.ts`), permission-checked by `src/lib/rbac.ts`.
- **Upload a document** — server action → `optimize.ts` shrinks it (sharp for images, Ghostscript
  for PDFs) → `storage.ts` writes it to `UPLOAD_DIR` → a `StaffDocument` row is created. Viewing a
  file goes through `api/documents/[id]`, which checks the session **before** returning the file.
- **Emirates-ID auto-fill** — the New-Profile wizard sends the ID image to `eid-ocr.ts` → Claude
  returns structured fields → the form is pre-filled for a person to confirm.
- **Expiry alerts** — `src/instrumentation.ts` starts a node-cron job (default 02:00 Asia/Dubai) →
  `notifications.ts` creates in-app alerts and emails escalations to managers via `mailer.ts`. Can
  also be run on demand from the Notifications page.
- **Auth** — `api/auth/[...nextauth]` + middleware protect every signed-in page; unauthenticated
  requests are redirected to `/login`.

## Access control (RBAC)

Five roles (Data Entry, Operations, HR/Admin, Finance, System Admin) plus two per-user flags.
Currently **every user can view/create/edit/approve staff & documents**; the **Settings** page is
**System-Admin-only**, and **adding/editing/removing user accounts** additionally requires the
**Super Admin** flag. All of this is enforced **server-side** in `src/lib/rbac.ts` and the settings
actions — never just hidden in the UI.
